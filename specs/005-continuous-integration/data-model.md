# Data Model: Continuous Integration and Plug-in Downloads

Nothing here is stored by the plug-in. The entities are what GitHub holds for the repository; the names and values are fixed in [contracts/ci-interface.md](contracts/ci-interface.md).

## Check run

One run of the Build workflow for one commit.

| Field | Value |
|---|---|
| Trigger | a pull request into `develop`, a push to `develop`, a push of a `v*` tag, or a manual run |
| Ref | `refs/pull/<n>/merge`, `refs/heads/develop`, `refs/tags/v<version>`, or the branch a manual run was started on |
| Jobs | `build`, `real-ide-tests`, `terminology` (pull requests only), `development-build` (`develop` only), `release` (`v*` tags only) |
| Result | success only when every job that ran succeeded |
| Outputs | each job's log, its summary with the skipped tests and their reasons, its test reports, the plug-in download, and the IDE logs when the real-IDE tests failed |

Rules: a newer run for the same pull request cancels the older one; runs for `develop` are never cancelled and run one after another.

## Plug-in download

The installable `etalii-adp-<version>.zip`.

| Field | Value |
|---|---|
| Version | `pluginVersion` in `gradle.properties` |
| Commit | the commit the check run built |
| Where | the check run (kept 90 days), the development build, or a versioned release (kept) |

Rule: a check run whose build step failed has no plug-in download, so nothing can be published from it.

## Development build

The single pre-release on the Releases page.

| Field | Value |
|---|---|
| Tag | `development`, moved to the published commit |
| Marked | pre-release, never "latest" |
| Title | `Development build <version> (<short sha>, <date>)` |
| Notes | the commit with a link, its subject, the UTC date, a link to the check run, and that every merge into `develop` replaces it |
| Asset | exactly one, `etalii-adp-<version>.zip` |

State: absent, then published for commit A, then replaced for a later commit B. It is replaced only by a check run on `develop` in which `build` and `real-ide-tests` passed and whose commit is ahead of the one `development` points at. A failed, cancelled or older run leaves it as it is.

## Version mark

A git tag `v<version>` on a commit of `develop`, pushed by a maintainer.

Valid when `<version>` equals `pluginVersion` at that commit and the commit is on `develop`. An invalid mark fails its check run in the `build` job's first step, with the reason, and nothing is published.

## Versioned release

| Field | Value |
|---|---|
| Tag | the version mark |
| Title | `<version>` |
| Marked | a full release; GitHub shows the newest as "latest" |
| Notes | generated by GitHub: the pull requests merged since the previous `v*` tag |
| Asset | `etalii-adp-<version>.zip` built from the marked commit |

State: absent, then published, and never changed. A second run for the same tag fails at "release already exists".
